# xcertplay 集成进车机桌面（App List）结论

> 记录如何让一个通过 `adb` 安装的第三方应用出现在领克 / 吉利 Flyme Auto 车机的
> 「我的应用」（App List）中，以及过程中定位到的两套过滤机制。
>
> 测试设备：`geely_fx11` / `CS11_A4`（Android 11，API 30）。

---

## 一、最终结论（TL;DR）

普通 `adb install` / `pm install` 的第三方应用**不会自动出现在车机桌面**，原因有两条，
需要分别打通：

| # | 场景 | 过滤条件 | 解决办法 |
|---|---|---|---|
| 1 | 底部状态栏（Bar / 底栏）长按后的「添加图标」选择器 | 过滤掉 `android:debuggable="true"` 的应用 | 安装 **release（非 debuggable）** 包 |
| 2 | 「我的应用」App List | 只收录**白名单**应用（见下） | 往应用商店 provider 写入一条记录 |

两条都打通后，`xcertplay` 成功出现在「我的应用」页面。

---

## 二、现象

- 车机上有一个 `xcertplay`（`com.shilapi.xcertplay`）的 release 包，`pm list packages`、
  `cmd package query-activities -a MAIN -c LAUNCHER` 都能查到，但：
  - 打开「我的应用」列表看不到它；
  - 用桌面搜索也搜不到；
  - 长按底栏进入的「添加到底栏」选择器里也看不到它（debug 包时）。

对照实验：安装 GitHub 上的开源 APK **Markor**（release 包）后，
底栏选择器里**能看到 Markor**，说明系统本身并不排斥新装的第三方应用。

---

## 三、根因一：底栏选择器过滤 `debuggable` 应用

对比 APK 的 manifest：

| APK | `android:debuggable` | 底栏选择器是否可见 |
|---|---|---|
| DiPlay-0.2.13（release） | 无 | ✅ |
| Markor（release） | 无 | ✅ |
| xcertplay `mobile-debug.apk` | **`true`** | ❌ |
| xcertplay `mobile-release.apk` | 无 | ✅ |

**结论：车机底栏的「添加图标」选择器会过滤掉 `debuggable=true` 的应用。**
因此不要直接装 debug 包，需构建并安装 release（非 debuggable）包。

> debug 包验证：
> `aapt dump xmltree mobile-debug.apk AndroidManifest.xml | grep debuggable`
> → `android:debuggable=0xffffffff`

---

## 四、根因二：「我的应用」是白名单驱动

### 4.1 数据来源

反编译桌面 `com.android.launcher3`
（`/system/priv-app/OneOS-Launcher3/OneOS-Launcher3.apk`）后，关键逻辑在：

- `com.geely.model.db.repository.ShortcutDbRepository`
  - `loadAvailableShortcut(i, apps)` —— 组装「可用白名单」：
    1. `parseShortcutsFromAssets(i)`：读取 APK 内 assets 的配置
       `assets/system_app_config_a1.json`（部分车型用 `_a2` / `_vp`）
    2. `parseShortcutsFromAppStore(i)`：读取**应用商店 provider**
    3. `appInfo.isShortcut()` 的应用
  - `filterAndSortShortcutEntity(...)`：只有出现在上述白名单里的应用才会被显示。
- `com.geely.view.appstore.repository.AppStoreHelper#loadAppStoreAppsData`
  → 查询 `content://com.geely.appstore.AppstoreProvider/appInfo`。

也就是说：

```
App List 显示的应用 = 已安装 ∩ ( asset 配置白名单 ∪ 商店 provider 记录 ∪ shortcut )
```

- **asset 配置**在系统分区 APK 内，只读，无法修改；
- **商店 provider** 是可写的（见第五节）。

### 4.2 只读的观测点

桌面还导出了一个只读 provider，可以查看它记录的 list：

```bash
adb shell content query --uri content://com.android.launcher3.interactive/shortcutEntity
# Row: 0 pakcageName=com.geely.appstore,        sortId=0,  itemType=1
# ...
# Row: 25 pakcageName=com.shilapi.xcertplay,    sortId=46, itemType=2   # ← 写入后出现
```

- `itemType=1`：asset 配置里的系统应用；
- `itemType=2`：商店 provider 收录的应用；
- 该 provider 的 `insert/update/delete` 均为空实现，**只读**。

## 五、解决办法：写入应用商店 provider

### 5.1 关键发现

应用商店（`com.geely.appstore`，`/system/app/OneOS-AppStore/OneOS-AppStore.apk`）的
`AppStoreProvider`：

- authority：`com.geely.appstore.AppstoreProvider`
- 表：`t_app_info`，URI：`content://com.geely.appstore.AppstoreProvider/appInfo`
- 支持 `insert`；
- 其权限 `com.geely.appstore.APPSTORE_PROVIDER`
  **`android:protectionLevel = normal`** —— **任何应用只要声明 `uses-permission`
  就会被自动授予**，从而可以读写该 provider。

`t_app_info` 列：

```
_id, package_name, apk_name, apk_icon, apk_size,
apk_version_name, apk_version_code, apk_type, apk_type_name, display_screen
```

### 5.2 做法

用一个声明了该权限的小工具 APK，往 `/appInfo` 插入一行我们的包，例如：

```
package_name   = com.shilapi.xcertplay
apk_name       = xcertplay
apk_type_name  = 常用工具        # 含「游戏」会变成 itemType=3
display_screen = 0
```

桌面重启后会把它以 `itemType=2` 收录进自己的 DB，并显示在「我的应用」里。

### 5.3 Helper 源码

`AndroidManifest.xml`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.xcertplay.mfihelper"
    android:versionCode="1" android:versionName="1.0">

    <uses-sdk android:minSdkVersion="28" android:targetSdkVersion="28" />

    <!-- 商店 provider 权限是 normal，声明即被授予 -->
    <uses-permission android:name="com.geely.appstore.APPSTORE_PROVIDER" />

    <application android:label="MFI Helper" android:debuggable="false">
        <receiver android:name=".HelperReceiver" android:exported="true">
            <intent-filter>
                <action android:name="com.xcertplay.helper.ADD" />
                <action android:name="com.xcertplay.helper.CHECK" />
            </intent-filter>
        </receiver>
    </application>
</manifest>
```

`HelperReceiver.java`：

```java
package com.xcertplay.mfihelper;

import android.content.*;
import android.database.Cursor;
import android.net.Uri;
import android.util.Log;

public class HelperReceiver extends BroadcastReceiver {
    private static final String TAG = "mfihelper";
    private static final Uri APPINFO =
            Uri.parse("content://com.geely.appstore.AppstoreProvider/appInfo");
    private static final String PKG = "com.shilapi.xcertplay";

    @Override
    public void onReceive(Context context, Intent intent) {
        String action = intent != null ? intent.getAction() : null;
        try {
            ContentResolver cr = context.getContentResolver();
            if ("com.xcertplay.helper.CHECK".equals(action)) {
                Cursor c = cr.query(APPINFO, null, null, null, null);
                if (c != null) {
                    Log.i(TAG, "t_app_info rows=" + c.getCount());
                    while (c.moveToNext()) {
                        Log.i(TAG, "row pkg=" + c.getString(c.getColumnIndexOrThrow("package_name"))
                                + " name=" + c.getString(c.getColumnIndexOrThrow("apk_name")));
                    }
                    c.close();
                }
                return;
            }
            Cursor c = cr.query(APPINFO, new String[]{"_id"}, "package_name=?",
                    new String[]{PKG}, null);
            boolean exists = c != null && c.getCount() > 0;
            if (c != null) c.close();
            if (exists) { Log.i(TAG, "already present: " + PKG); return; }

            ContentValues v = new ContentValues();
            v.put("package_name", PKG);
            v.put("apk_name", "xcertplay");
            v.put("apk_type_name", "常用工具");
            v.put("display_screen", "0");
            v.put("apk_version_name", "1.3.3");
            v.put("apk_version_code", 1303);
            v.put("apk_type", "0");
            Log.i(TAG, "insert result=" + cr.insert(APPINFO, v));
        } catch (Throwable t) {
            Log.e(TAG, "error", t);
        }
    }
}
```

### 5.4 免 Gradle 手动构建（build-tools 37.0.0）

```bash
BT="$HOME/Android/Sdk/build-tools/37.0.0"
JAR="$HOME/Android/Sdk/platforms/android-37.0/android.jar"

javac -source 11 -target 11 -cp "$JAR" -d classes \
    src/com/xcertplay/mfihelper/HelperReceiver.java
"$BT/d8" --lib "$JAR" --min-api 28 --output dexout $(find classes -name '*.class')
"$BT/aapt" package -f -M AndroidManifest.xml -I "$JAR" -F unsigned.apk
( cd dexout && "$BT/aapt" add ../unsigned.apk classes.dex )
"$BT/zipalign" -f 4 unsigned.apk aligned.apk
"$BT/apksigner" sign --ks test.jks --ks-pass pass:android --key-pass pass:android \
    --ks-key-alias xcertplay --out helper.apk aligned.apk
```

安装并触发：

```bash
./install-apk.sh helper.apk
adb shell am broadcast -a com.xcertplay.helper.ADD \
    -n com.xcertplay.mfihelper/.HelperReceiver
adb logcat -d -s mfihelper:V
```

## 七、注意事项

- 需要安装 **release（非 debuggable）** 包；debug 包在底栏选择器中会被过滤。
- 重新构建 release 需要签名；未配置 `ANDROID_KEYSTORE_*` 时自行生成一个即可，
  签名与已装包不一致时需先卸载旧包。
- 商店 provider 的记录可能会在应用商店同步 / 刷新时被清理，届时重跑 Helper 的
  `ADD` 广播即可。
- Helper 只插入、不提供「删除全部」，因为该 provider 的 `delete(appInfo)`（无 `_id`）
  会清空整张 `t_app_info`；如需移除请按 `_id` 用 `content://.../appInfo/<id>` 删除。
- 这是针对**用户自有车机**的本地集成手段，非官方安装渠道。
