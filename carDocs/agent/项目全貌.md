## 1. 项目是什么

**DiPlay / lynkPlay**：在 Android 车机上实现 Apple **CarPlay 接收端**（receiver）的开源项目。
iPhone 插 USB 或连 Wi-Fi 后，车机屏幕出现 CarPlay 界面（导航、音乐、Siri、电话），支持触控回传。

- 上游：[shihabal3amri/DiPlay](https://github.com/shihabal3amri/DiPlay)（原名 xcertplay，GPL-3.0，基于 shilapi/xcertplay），面向**比亚迪 DiLink** 车机，最新 v0.2.19。
- 本仓库：[macheteHot/DiPlay](https://github.com/macheteHot/DiPlay) 的 **lynk 分支**——把 DiPlay 适配到**领克/吉利 FX11 车机**的定制分支，用户可见品牌 **lynkPlay**。
- 目标车机：`geely_fx11` / 型号 `CS11_A4`（领克，德赛西威 DesaySV 代工，ECARX/亿咖通软件栈，高通 SA8155，Android 11 API 30，桌面为 Flyme Auto 定制 Launcher3）。
- 包名：`com.shihab.diplay`（release）/ `com.shihab.diplay.hudtest`（debug）；入口 `com.shilapi.xcertplay.DiPlayActivity`。

**一句话**：上游解决"比亚迪车机跑 CarPlay"，lynk 分支解决"领克 FX11 车机跑 CarPlay"，且全部改动按设备门控、不破坏比亚迪行为。

## 2. 模块与架构

Gradle 模块（`settings.gradle.kts`，rootProject 名 `xcertplay`）：

| 模块 | 角色 |
|---|---|
| `shared` | **协议引擎**（纯 Kotlin，614 个源码文件）：airplay（AirPlay/CarPlay 会话、音频流、配对加密）、iap2（iAP2 协议分层：wire/message/session/catalog/body/trace）、transport（USB usbmuxd/NCM/蓝牙 RFCOMM/TLS 等链路）、network（Bonjour、热点、VPN、Wi-Fi Direct）、media（MediaCodec 解码、AudioTrack、麦克风 Opus 上行、触摸映射）、mfi（MFi 认证：iAP2 隧道 / I²C 直连协处理器）、hud（车厂桥：比亚迪 HUD/仪表/氛围灯 + 吉利集群）、adb（本机 adbd 客户端）、orchestration（`CarPlayController` 总状态机）、telecom、location、compat、jni（speexdsp）、org.concentus（Opus） |
| `common` | **车机适配 + UI 层**（299 个文件）：全部 Activity/Service/Receiver、设置界面（`DiPlayActivity` 六千行）、设置持久化 `AirPlayPersistence`、比亚迪/吉利 HUD 集成、诊断导出、多语言资源 |
| `mobile` | 打包壳（application，`com.shihab.diplay`，几乎无代码，清单合并 + 品牌） |
| `automotive` | 上游继承的 Automotive 变体（基本空） |
| `samples/home` | 可选桌面 launcher 示例 |
| `samples/maphost` | 地图内嵌宿主示例（`EMBED_MAP` action） |
| `samples/carprobe` | **车机 API 探针**（Java，诊断用，不发布）：实测 HUD/仪表/DIM/OneOS 通道 |
| `carDocs/` | 中文适配记录与车机逆向文档（本分支核心知识资产） |

**CarPlay 数据链路**（简版）：

- 有线：iPhone USB → `Iap2UsbMuxHost`（usbmuxd 帧）→ iAP2 会话 → MFi 认证（iAP2 隧道 `Iap2MfiAuthenticationClient` 或 I²C 直连协处理器 `LocalMfiAuthenticationClient`）→ iAP2 内开 AirPlay 隧道 → H.264/H.265 视频 + AAC 音频。
- 无线：`CarPlayController` 先起本地热点/加入既有 Wi-Fi + 蓝牙 RFCOMM 唤醒 → Bonjour 广播 `_airplay._tcp` → iPhone 连入 → MFi SAP 认证 → AirPlay RTSP（视频 TCP、实时音频 UDP、缓冲音乐 TCP）。
- 输出：MediaCodec 解码 → `AndroidMediaSink`/Surface 显示；音频 → AudioTrack；触摸 → HID/iAP2 回传 iPhone；导航/仪表 → `hud/` 车厂桥。
- 认证身份：APK 内嵌实验性 accessory 身份（MFi 凭据，提取自公开 Carlinkit 固件；本分支则从车机现有安装提取，见 `carDocs/build-lynk.sh`）。

**状态持久化（应用自身的）**：全部 SharedPreferences，无数据库。
核心是 `common/.../AirPlayPersistence.kt`（单文件 `xcertplay_airplay`，1300+ 行、100 多个键）：
MFi 身份私钥/公钥、配对记录（Lockdown 证书链）、显示缩放/HEVC/音频通道/缓冲、热点凭据、仪表安全区等。
诊断报告走 `DiagnosticExportStore`（优先 MediaStore Downloads/DiPlay，退回 FileProvider，`DiagnosticRedactor` 脱敏）；
另有设置二维码备份（`SettingsBackupCodec`）、崩溃记录（`CrashRecord`）、有界日志（`BoundedDiagnosticWriter`）。

## 3. lynk 分支改动清单（相对上游 origin/main，42 个提交）

**门控体系（关键设计）**：两级布尔门控，比亚迪车型上全部为 false，行为与上游一致——
- `GeelyHeadUnit.detected`（`shared/.../network/GeelyHeadUnit.kt`）：按 `Build.PRODUCT/MODEL/ID` 识别吉利车机，上游方向盘键/麦克风路径已用它；
- `LynkHeadUnit.detected`（= 前者）：本分支新增行为的统一开关（`shared/.../network/LynkHeadUnit.kt`）。

| 改动 | 文件 | 说明 |
|---|---|---|
| 车机常量与 Wi-Fi 自启 | `LynkHeadUnit.kt` | P2P 信道默认 **149**（该车框架拒绝 36）；`ensureWifiEnabled()` 经本机 adbd 执行 `cmd wifi set-wifi-enabled enabled`（App 自身无权限，adbd 已授权时静默完成；注意本车 adbd 不监听 TCP，实际靠"关热点保 Wi-Fi"跨重启保持，见第 4 节）；`OEM_LABEL="LYNK & CO"` |
| Wi-Fi Direct 建组前自动开 Wi-Fi | `WifiP2pGroupManager.kt` | Wi-Fi 关且 detected 时先 `ensureWifiEnabled`（等 8s）再建组 |
| 设置默认值分叉 | `AirPlayPersistence.kt` | 缓冲音乐默认**开**（实时音频不可用，见下）；音乐缓冲默认 **500ms**（实时流只活 ~1.7s，大缓冲永远填不满导致轨道不启动）；设置手势默认 4 指；底栏默认不隐藏；OEM 标签强制替换 BYD→LYNK & CO（即使之前存过 BYD）；manufacturer/model=lynkPlay；新增 launcher 气泡两个键 |
| 麦克风修复（Siri） | `MicrophoneUplink.kt` | speechrecognition 录音源改 `VOICE_COMMUNICATION`（该车只对此源真开麦；`VOICE_RECOGNITION` 录到静音） |
| Siri 麦克风即开 | `CarPlayMediaEngine.kt` | 流建立后立即启动麦克风（原延时静默） |
| 反馈时钟 | `/feedback` sampleTime 绑定已收样本 | 修通话/导航语速过快一类问题 |
| 方向盘键 | `GeelyWheelKeys.kt` + AIDL | 订阅车机 `com.geely.inputservice` 私有键（200085/200087/200088/200231，`IInputManager.registerListener` 无权限校验）；上游已有，本分支补双发防护测试；媒体键改由车机蓝牙链路接管（车蓝牙持有方向盘媒体键） |
| CarPlay 音频走车蓝牙（可选） | `AirPlayPersistence.loadCarBluetoothAudio` | `disableAudioOutput=true`，音乐/导航/通话全走 iPhone↔车机 A2DP/HFP；绕开 UDP 丢包；实验性默认关 |
| 仪表投屏 | `GeelyClusterDisplay.kt`（新） | 仪表 = display 2（1920x720、FLAG_PRESENTATION、设备 `msmnile_gvmq` 门控）；`streamConfig()` 输出整屏流 + 安全区 |
| 仪表投影开关 | `GeelyClusterProjection.kt`（新） | 反射取 `DimNaviService` binder 直发事务码 9（`notifyDimProjectScreenSwitch`）——**不开投影，Presentation 会被原厂表盘盖住**；`ClusterMapPresentation` onStart/onStop 开关 |
| Launcher 悬浮球 | `LauncherBubble.kt`（新，398 行） | `SYSTEM_ALERT_WINDOW` 悬浮球：DiPlay 不在前台时显示；单击回 CarPlay；拖动换位持久化；长按 900ms 锁定/解锁位置。背景：该车桌面只放自家卡片，气泡是回 CarPlay 的唯一可靠入口 |
| 车机探针 | `samples/carprobe` | 一次性探测车机 HUD/仪表/DIM/OneOS API（产出第 4 节结论的工具） |
| 品牌化 | mobile/home/maphost/多语言 | 文案/图标 → lynkPlay / LYNK & CO / Lynk 车按钮图标 |
| 文档与工具 | `carDocs/`、`udp-soak` | 中文适配记录、整机逆向 14 篇、UDP 丢包诊断法、安装/构建脚本 |

**遗留注意**：`LynkHeadUnit.MEDIA_BUFFER_MILLIS = 2000` 不是默认值，只是设置界面在此车机上**多出的一个预设档位**；实际默认 500ms 在 `AirPlayPersistence.loadMediaBufferMillis`。

## 4. 目标车机适配结论（实测定案）

### 4.1 可用能力（本分支已用/已验证）

| 能力 | 通道 | 状态 |
|---|---|---|
| 无线 CarPlay（画面/触控/iAP2） | Wi-Fi Direct 5GHz **channel 149** | ✅ 日常可用 |
| CarPlay 音频（音乐） | 「缓冲音乐」TCP `type=103` | ✅ 可用（默认开） |
| CarPlay 音频（全量，可选） | 车机蓝牙 A2DP/HFP | ✅ 实测有效（实验性，默认关） |
| 方向盘切歌键 | `IInputManager.registerListener` 私有键码 | ✅ 可用 |
| 长按麦克风键 → Siri | 停用 HiCar（`pm disable-user com.geely.hicar`）+ 订阅 200231 | ✅ 可用 |
| Siri 听得见 | 车机 secure 设置 `app_permission_mic_<pkg>=0` + `VOICE_COMMUNICATION` 源 | ✅ 可用 |
| CarPlay 画面投仪表 | `Presentation` → display 2 + `notifyDimProjectScreenSwitch(true)` | ✅ 2026-10-13 打通 |

### 4.2 死路清单（勿再踩）

| 死路 | 原因 | 出处 |
|---|---|---|
| **有线 CarPlay** | 本车 USB 是 accessory/AOA 角色，未声明 `usb.host`，USB 由 native/QNX 层掌管，应用层看不到 iPhone | headunit/14 |
| **实时 UDP 音频**（实时音乐/导航提示/通话/Siri 声音） | 车机 Wi-Fi 对持续入站 UDP 丢包 77~87%（跨两个 AP 复现，驱动/固件层，应用改不了） | 车机兼容记录 §十、上游 issue #165/#131 |
| **HUD/仪表导航内容注入** | DIM 导航协议只接收不渲染；渲染只由原厂地图引擎（OneOS `INaviServer` ← `com.geely.map`）驱动；禁用原厂地图后仪表/HUD 依然不显示第三方数据 | 仪表与HUD调研 §八/九 |
| **仪表地图宿主**（模仿地图 app 加 Surface） | 原厂配置 `isOpenHud=false`，HUD 引擎永不初始化，静默失败 | 地图HUD显示机制 |
| **`DimService` 直绑** | `onBind` 返回 null | headunit/05 |
| **广播加桌面图标** | Launcher 未注册 `INSTALL_SHORTCUT` 接收器；白名单在只读 assets | 车机安装与桌面说明 §三 |
| **U 盘裸装 APK / 静默安装权限** | 无文件管理器 UI 入口；`INSTALL_PACKAGES` 为 signature|privileged | headunit/13 |
| **普通 `adb install`** | 不支持流式安装 + adbd 切断含 `install` 的命令（用 `carDocs/install-apk.sh`） | 车机安装与桌面说明 §二 |
| **Wi-Fi 与车载热点并存** | 单 Wi-Fi 芯片互斥；开机默认开热点顶掉 Wi-Fi 客户端 | 车机兼容记录 §七 |
| **本机 adbd TCP** | `persist.adb.tcp.port` 无效，`adb tcpip` 不可用，只能 USB | 车机兼容记录 §七实测 |

### 4.3 从零安装一台同款车（摘要）

1. `./carDocs/install-apk.sh mobile-release.apk`（release 包才能进底栏选择器）；
2. 车机设置里**关车载热点**，开 Wi-Fi（之后跨重启保持）；
3. `adb shell pm disable-user --user 0 com.geely.hicar`（麦克风键长按让给 Siri）；
4. `adb shell settings put secure app_permission_mic_com.shihab.diplay 0`（车机侧麦克风授权）；
5. 需要声音时开「缓冲音乐」或「车机蓝牙音频」。
完整版与排错表：`carDocs/同款车机安装指南.md`。

## 5. 构建与验证

```sh
# 构建（需 JDK 25 + Android SDK 37 + NDK 28.2；release 需外部 MFi 资产目录，见 carDocs/build-lynk.sh）
./gradlew :mobile:assembleDebug

# CI 全量检查（AGENTS.md 规定，改代码后必跑）
./gradlew :shared:testDebugUnitTest :common:testDebugUnitTest :home:testDebugUnitTest \
  :mobile:lintDebug :home:lintDebug :maphost:lintDebug \
  :mobile:assembleDebug :home:assembleDebug :maphost:assembleDebug

# 单测吉利仪表改动
./gradlew :common:testDebugUnitTest --tests "com.shilapi.xcertplay.GeelyClusterDisplayTest"
```

- 纯文档改动可跳过构建，但须在《会话日志》注明。
- **安全红线**：release 构建内嵌从车机提取的 MFi 身份（Apple 凭据）。**不公开分发 APK**；对外只分享源码 + `carDocs/build-lynk.sh`，让使用者用自己的车机资产自行构建。
