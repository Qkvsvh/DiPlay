# 同款车机安装指南（吉利/领克 FX11 · CS11_A4）

> 适用车机：`geely_fx11` / 型号 `CS11_A4`（DesaySV 德赛西威，`msmnile` 即高通 SA8155，Android 11）。
> 桌面为 Flyme Auto 定制 Launcher；系统栏 `com.geely.statusbar`；原厂 CarPlay 服务 `com.autolink.carplay`。
> 本指南是**从零到可用**的完整步骤。细节与实测出处见各节末尾的「详见」引用。

---

## 0. 前提与准备

- **电脑**：装好 `adb`，用 USB 线连车机。本车 adbd **不监听 TCP**，只能 USB（`adb tcpip` 无效）。
- **APK**：`mobile-release.apk`
  - 包名 `com.shihab.diplay`，签名 `CN=DiPlay Lynk`（自签，和官方发布签名不同）。
  - 由发布者提供；或按 `carDocs/build-lynk.sh` 自行构建（会从车机现有安装里提取 MFi 资产）。
- **口径**：本车的 adbd 会**过滤命令里的 `install` 字样**（吉利/领克防篡改），安装命令必须拆分写法，见第 1 步。
- **⚠️ 安全**：构建产物内嵌了**从你车机提取的离线 MFi 身份**（Apple 凭据）。**不要公开分发 APK**；对外只分享源码 + 脚本，让使用者用**自己车机**的资产自行构建（`build-lynk.sh` 会自动提取）。

---

## 1. 安装 APK（本车不能用普通 `adb install`）

本车不支持增量/流式安装，且 adbd 会切断含 `install` 的命令。正确做法：

```bash
# ① 推送
adb push mobile-release.apk /data/local/tmp/mobile-release.apk

# ② 拆分关键字调用 pm install（命令原文里不能出现 install）
adb shell 'a=in; b=stall; pm ${a}${b} -r -t /data/local/tmp/mobile-release.apk'
# 期望输出：Success
```

或直接用配套脚本（内部已拆分）：

```bash
./carDocs/install-apk.sh mobile-release.apk        # 默认 -r -t
./carDocs/install-apk.sh mobile-release.apk -r -t -d
```

### 换签名要卸载旧包

自签与官方发布签名不同。若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，先卸载（`uninstall` 同样含 `install`，也要拆分）：

```bash
adb shell 'a=ins; b=tall; pm un${a}${b} com.shihab.diplay'
```

> 卸载会清掉旧设置。

**详见**：`车机安装与桌面说明.md` 第二节。

## 2. 打开 Wi-Fi（无线 CarPlay 必需）

这台车**单个 Wi-Fi 芯片**，**「车载热点」和 Wi-Fi 客户端互斥**。开机默认会打开车载热点，把 Wi-Fi 客户端顶掉，于是 DiPlay 起不了无线。

**做法**：

1. 车机 **设置 → 系统 → 连接** 里**关掉「车载热点」**；
2. 再把 Wi-Fi 打开一次（或执行下面命令）：

```bash
adb shell cmd wifi set-wifi-enabled enabled
adb shell settings get global wifi_on      # 校验 =1
```

- 关掉车载热点后，**Wi-Fi 状态可跨重启保持**，之后不需要每次用 adb。
- 注意：电脑要连车机做无线调试时，不要让车机同时连着别的 Wi-Fi（会占用 P2P）。

**详见**：`车机兼容记录.md` 第七节。

## 3. 方向盘麦克风键 → Siri（停用 HiCar）

方向盘键是**厂商私有键码**，DiPlay 通过车机的输入服务订阅（自动生效，无需手动设置）。
但**麦克风键长按默认被 HiCar 抢走**（`startHiCarMainActivity`），DiPlay 拦不住，所以**停用 HiCar**：

```bash
adb shell pm disable-user --user 0 com.geely.hicar

# 校验：期望 enabled=3 (DISABLED_USER)、stopped=true
adb shell dumpsys package com.geely.hicar | grep -E "enabled=|stopped="

# 需要恢复时
adb shell pm enable com.geely.hicar
```

> 这是**系统层设置**，不是 App 开关；系统 OTA 后可能要重跑。
> 停用后：长按麦克风键 → `requestSiri()`；短按仍是车机自带语音助手（应用侧拦不到）。

**详见**：`车机兼容记录.md` 第六节。

---

## 4. 车机麦克风授权（否则 Siri 听不到）

车机自带的权限服务默认**拒绝**第三方 App 的麦克风，DiPlay 录到的会是 DTX 静音帧。授权：

```bash
adb shell settings put secure app_permission_mic_com.shihab.diplay 0
```

> `0`=授权，`-1`=拒绝（默认）。DiPlay 分支里 Siri 的录音源已改为 `VOICE_COMMUNICATION`（本机语音助手也是用它）。

**详见**：`车机兼容记录.md` 第八节。

## 5. 桌面图标与品牌

- 车机桌面是深度定制的 Launcher，**没有注册第三方快捷方式接收器**，不能用广播加图标。
  在「我的应用」里**长按 DiPlay 图标 → 添加到桌面**（或拖到首页卡片区）。
- lynk 分支已把用户可见文案/图标品牌化为 **lynkPlay / LYNK & CO**，CarPlay 里的车辆按钮也已从 `BYD` 改成 `LYNK & CO`。

**详见**：`车机安装与桌面说明.md` 第三节。

## 6. ⚠️ 已知限制：实时音频（重要）

**这台车机的 Wi-Fi 接收对持续入站 UDP 有严重丢包（实测约 77~87%）**，因此：

- CarPlay **实时音频走 UDP、无重传** → 音乐/导航/通话/Siri **几秒后就断**（这是车机固件问题，应用层改不了）；
- 可用路径：
  - **设置 → 高级 → 缓冲音乐（实验性）**：媒体走 TCP（`type=103`）。**只覆盖媒体，导航提示音没有缓冲流**；
  - **设置 → 高级 → 通过车辆蓝牙播放 CarPlay 音频（实验性）**：全部改走车机蓝牙。可覆盖导航/通话，但**导航混在 A2DP 主声道、没有独立导航声道、不能单独调音量**；
- 两方案都是**实验性、默认关闭**，需要手动打开。

**详见**：`车机兼容记录.md` 第九、十节（含跨 AP 实测数据与上游 issue #165/#131）。

## 7. 验收清单

- [ ] 包列表里能看到 `com.shihab.diplay`，版本号正确（`adb shell pm list packages | grep shihab`）
- [ ] `settings get global wifi_on` = 1，且车机设置里「车载热点」为关
- [ ] 无线 CarPlay 连上（画面 + 触控正常）
- [ ] 方向盘：切歌/音量正常；长按麦克风键唤起 Siri，说话有反应
- [ ] 需要媒体声音时，打开「缓冲音乐」或「车机蓝牙」

## 8. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `adb install` 失败 / `error: closed` | 本车不支持流式安装 + adbd 过滤 `install` | 用第 1 步的 push + 拆分 |
| 安装报签名不一致 | 官方签名 vs 自签 | 先卸载（第 1 步末尾）再装 |
| DiPlay 提示「请在车机设置中打开 Wi-Fi」 | 车载热点把 Wi-Fi 顶掉 | 关车载热点，再开 Wi-Fi（第 2 步） |
| 长按麦克风键唤醒 HiCar 而非 Siri | HiCar 占用 | 停用 HiCar（第 3 步） |
| Siri 能唤起但说话没反应 | 车机麦克风权限被拒 | 授权（第 4 步） |
| 音乐响一两秒就没声 | 车机 Wi-Fi UDP 丢包 | 走缓冲音乐 / 车机蓝牙（第 6 步） |
| `waiting for device` 死循环 | USB 通道错乱 | 重新插拔 / `adb kill-server && adb start-server` |
