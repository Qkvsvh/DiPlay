# 氛围灯 / 灯光：谁在控制、怎么控、协议

> 对象：吉利 FX11（`geely_fx11`/`CS11_A4`）车机的氛围灯、阅读灯、脚窝灯、迎宾/送别灯与「灯光秀」。
> 证据：REA 反编译 + `dexdump` 常量（`evidence/inspect/amb.*`、`evidence/method/amb.*`）。

## 一、结论：控制的 APK / 进程

| 层 | 组件 | 作用 |
| --- | --- | --- |
| **UI** | **`com.geely.settings`**（MyCar → 灯光/氛围灯） | 氛围灯设置界面；**内含「灯光秀」`com.geely.commoncomponents.lightshow.*`**（Wi-Fi TCP 服务器 + HTTP + Excel→JSON + 动画） |
| 灯效秀 App（未装） | `com.autofuture.lightshow`（白名单里有，本车**未安装**） | 独立灯光秀 App（本车缺） |
| **对外 API** | `ecarx.adaptapi.jar`：`com.ecarx.xui.adaptapi.car.vehicle.Lamp` / `ILamp`、`com.ecarx.xui.adaptapi.lightshow.LightShowImpl` / `lighting.ILightingShow` | 车辆灯光（含外饰）与灯光秀的 ECARX 官方 API |
| **实际控制器** | `ecarx.car.jar`：**`ecarx.car.hardware.vehicle.ECarXCarAmbliManager`**（运行于 `com.ecarx.car` / `ECarXCarService`） | 真正的读/写：`CB_AmbLi*` / `CB_Zone*` / `CB_MoodLight*` / `CB_ReadLight*` + `ManagerId_*` 属性 ID |
| 外饰灯光秀 | `fw-autolink.adapterservice`：`com.autolink.adaptersrv.tcam.ExteriorLightShowImpl`、`ecarx.fw.api.tcam.TcamServiceLarkLightShowCallbackListener` | 外饰灯光秀（TCAM） |
| 音乐/语音律动 | `com.autolink.audioextservice`：`MusicLightShowBean`、`VoiceLightShowBean`、`IExteriorLightShowCallBack` | 音乐/语音驱动的灯效 |
| 车信号 | `ecarx.car.hardware.annotation.{AmbLiMod,AmbLiShowTyp,AmbLiWelcomeAudMod,VFMiscMoodLightCoulor,…}` | 最终 VehicleHAL/SOME/IP 信号名 |

> 所以：**UI 在 `com.geely.settings`，但真正下发灯光的是 ECARX 的 `ECarXCarAmbliManager`（`com.ecarx.car` 进程）**。

## 二、控制通道（第三方/程序化）

1. **ECARX 属性（主通道）**：`ecarx.car.hardware.vehicle.ECarXCarAmbliManager`
   （`ecarx.car.jar`，在 boot classpath；服务端在 `com.ecarx.car`）。
   读：`getPA_*()`（如 `getPA_AmbLiAll()`、`getPA_Zone1ColorSettings()`）；
   写：`CB_*()`（如 `CB_AmbLiAll(int)`、`CB_Zone1ColorSettings(int)`），返回 `ApiResult`。
   —— 需要 Car API/厂商权限（第三方默认拿不到，需实测）。
2. **ECARX 适配 API**：`com.ecarx.xui.adaptapi.car.vehicle.Lamp`（`ILamp` 常量 + 功能号）、
   `com.ecarx.xui.adaptapi.lightshow.LightShowImpl`（灯光秀）。
3. **灯光秀（LightShow）**：`ILightingShow` / `LightShowImpl`
   `setLightingShowType/Mode`、`startLightingShow()/stopLightingShow()`、
   `sendLightingShowSource(byte[])`、`getVehicleIpTable(int)`、`sendIpMessage(int,String)`、
   `registerLightingShowWatcher(...)`；错误码 `ERROR_CODE_{NO_ERROR,BATTERY_LOW,BRAKE_PRESSED,DOOR_NOT_CLOSED,WINDOW_NOT_DOWN,HWL_ON,LAMP_FAULT,ACC_NOT_CONVENIENCE}`。

## 五、协议三：灯光秀（Light Show）传输

- **车端 IP 角色**：`ILightingShow.getVehicleIpTable(int)`，常量 `VEHICLE_IP_INTERNET_MASTER` /
  `VEHICLE_IP_LOCAL_MASTER` / `VEHICLE_IP_LOCAL_SLAVE`；`sendIpMessage(int, String)`。
- **下发**：`sendLightingShowSourceStart()` → `sendLightingShowSource(byte[])`（分片）→ `sendLightingShowSourceEnd()`；
  `setLightingShowType/Mode`、`startLightingShow()/stopLightingShow()`。
- **状态/错误**：`getLightingShowState()`（IDLE/PREPARE/START/SHOWING/STOP/END/ERROR/UNKNOWN）、
  `getLightingShowError()`、`getLightingShowInfo(int)`（`ILightingShowInfo[]`）、`getLightShowCarConfig()`。
- **应用侧（`com.geely.settings`）**：
  - `com.geely.commoncomponents.lightshow.lightserver.GlyTCPServer` / `GlyAndroidWiFiTCPServer`
    —— `new ServerSocket(0, 50, inetAddress)`（**动态端口**），`serve(clientSocket)` 收数据；
  - `com.geely.commoncomponents.lightshow.http.GlyHttpAndServer(host, port)` —— HTTP 服务（默认 `default` 配置，10s 超时）；
  - `com.geely.commoncomponents.lightshow.json.GlyExcelToJson` / `GlyExcelModel` / `GlyJsonToBeanList`
    —— **把 Excel 灯效表转 JSON**；
  - `util.GlyAnimationsContainer` / `CarAnimUtils` / `GlyAppUtils` / `GlyPopUtils`。
  → 即：**灯光秀 = 车端按 IP 表组网，配置由 Excel→JSON 生成，经 WiFi TCP/HTTP 下发，最终转成字节流
  `sendLightingShowSource(byte[])` 打到灯光控制器**（`ManagerId_cblightshowdata=561023163` 承载数据）。

## 六、车信号层（最终落到车辆总线）

注解/信号名（`ecarx.car.hardware.annotation.*`、`vendor.ecarx.xma.automotive.vehicle.V1_0.*`，
也出现在 AOSP `android.hardware.automotive.vehicle.V2_0`）：
`AmbLiMod`、`AmbLiShowTyp`、`AmbLiWelcomeAudMod`、`VFMiscMoodLightCoulor`、`AmbMode1`、`AmbReq2`、
`AmbTIndcdUnit`、`BattColuColor`、`AsyLineLeColor`、`PwrDoorWarn` …
→ 这些是 C 总线/SOME/IP 信号名，ECARX 的 `ECarXCarPropertyManager` 用它做 RX/TX。

## 七、第三方可行性 / 限制

| 通道 | 第三方可写？ | 备注 |
| --- | --- | --- |
| `ECarXCarAmbliManager.CB_*` | 取决于权限 | 类在 boot classpath，服务在 `com.ecarx.car`；需 Car/Vendor 权限（待实测） |
| `adaptapi.Lamp` / `LightShowImpl` | 官方 SDK，可能受 `FunctionStatus` 门控 | `isLightingShowEnabled()` 返回支持状态 |
| 灯光秀字节流 | 需要 `sendLightingShowSource` + IP 表 | 门槛较高，但协议结构已拿到 |
| VDBus/acar 信号直写 | 需权限 | 见 [`02`](02-框架与VDBus.md) |

## 八、验证命令（上车）

```sh
# UI 入口
adb shell am start -n com.geely.settings/.MainActivity            # MyCar → 灯光
# 工程模式里也有灯/影音测试页
adb shell am start -n com.desaysv.engmode/.MainActivity
# 车信号/属性（只读、需要厂商权限）
adb shell dumpsys car_service | grep -i -E 'AmbLi|MoodLight|readlight'
# VDBus / 灯效服务日志
adb logcat -s AudioExtService:* ECarXCarAmbliManager:* Lamp:*
```

> ⚠️ 注意：氛围灯/阅读灯多为**车控安全相关**（行驶中可能被限制），且读写走厂商属性，
> 第三方直接写有不被授权或影响行车体验的风险；建议只读探测 + 复用官方 UI。

## 九、一句话

**氛围灯 UI 在 `com.geely.settings`（含灯光秀 TCP/HTTP + Excel→JSON），真正下发的控制在
`com.ecarx.car` 进程的 `ecarx.car.hardware.vehicle.ECarXCarAmbliManager`（`ManagerId_*` 属性 ID 557877xxx）；
对外还有 `adaptapi.car.vehicle.Lamp` 与 `lightshow.LightShowImpl`（灯光秀，`sendLightingShowSource(byte[])`）。**
协议（属性 ID、功能号、灯光秀传输与 IP 表）已在本文件第三节至第六节列出。
