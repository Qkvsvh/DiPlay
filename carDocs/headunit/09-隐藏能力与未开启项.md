# 隐藏能力与「有但没开」的功能

> 结论：这台车机**有一批现成但没暴露给车主的能力**，分四类：
> ① 隐藏的**工程模式 / 调试服务**（最大的一块）；② 白名单宣称但本车**没预装**的功能；
> ③ **当前为关的状态开关**；④ **车型能力门控**（取决于配置，静态只能给清单）。
> 另有 ⑤ 平台里有、但没人用的 API（前文已知）。
> 证据：`extracted/system`（getprop / 各 APK）+ REA（`evidence/`）。以下均为静态观测。

## 一、隐藏的工程模式（`com.desaysv.engmode`）——最值得说的一块

- 包：`com.desaysv.engmode`（`product-app/SVEngMode`，label「**工程模式**」，versionName `Geely-8155_11...`）。
- 入口：`com.desaysv.engmode.MainActivity`，**`android:exported=true`** →
  `adb shell am start -n com.desaysv.engmode/.MainActivity` 可直接进。
- 它内嵌了 **Fairy 插件框架**（`com.limpoxe.fairy`）与 `installCustomEngmodeApp`，可**动态装插件页**。
- 页面（manifest 全表，约 45 个 Activity）：
  `VersionInfo`、`Wifi`、`Bt`、`ScreenTest`、`ScreenTouchTest`、`Tuner`、`Gps`、`Sources`、`Mic`、
  `Rvc`（后视）、`Dsp`、`Usb`、**`CarPlay`**、`IPod`、`Board`、`Sound`、**`Burn`（烧录）**、`Ethernet`、
  `Temperature`、`BatteryInfo`、**`Adb`**、**`OfflineConfig`（下线配置）**、`TboxInfo`、`GpsUpdate`、
  `USBAuth`、`Other`、`AppVersion`、`Third`、`VRUpdate`、`AllUpdate`、`TBOXUpdate`、`Exhibition`、
  `StrMode`、`FullScreen`、**`DTC`（故障码）**、`FileBrowse`、`LimitTest`、`Camera`、`SpeakerTest`、
  `CharacterTesting`、**`SelfDiag`（自诊断：含 GPS/MIC/TBOX 网络诊断）**。
- 关键能力：**546 个 `carconfigNNN` 车辆配置项**、`getDtcResult/parseDtcName`（读故障码）、
  `getAdbStatus`（ADB 开关）、`TBOX` 升级/查询、烧录（`setBurnStart/stopBurnTask`）、
  CarPlay 测试（`isCarplayITU`、`CarPlay_GOOD/Left`）、STR/演示模式。
- Service：`TaskListService`、`SafeLogService`；receiver `UsbBroadcast`/`PluginBroadcast`/`CustomBroadcast`。

> 这就是「车主看不到的隐藏菜单」：版本/硬件自检、诊断故障码、ADB、下线配置、TBOX/VR/GPS 升级、烧录、演示模式。

## 六、车型能力门控（`com.geely.utils.VehicleManager`，静态清单）

Launcher 用这些判断来决定组件/功能是否出现（实际值要上车读 `com.ecarx.xui.adaptapi.car.ICar`）：

```
isSupportAtmosphereLamp()    氛围灯
isSupportAvm()               全景影像
isSupportAutoPark()          自动泊车
isSupportFragranceFunction() 香氛
isSupportSeat(int) / isSupportSeatWidget()   座椅 / 座椅组件
isSupportSoundEffect() / isSupportSoundEffectWidget()  音效 / 音效组件
isCarSeat7()                 是否 7 座
getCarMode() / getTypeGear() / isInPGear()   驾驶模式 / 档位
```
组件门控（`parseAllWidget`）：A3 音效组件、A3 氛围灯组件、KX11 AVM、座椅组件、7 座香氛组件——
不满足车型能力就**不显示**。

## 七、平台里有、但没被用起来的能力（前文详述）

- **投屏服务** `com.desaysv.ivi.projection.IProject`（`startProjectToDisplayWithSurface`，服务 `com.desaysv.ivi.vds.projection`）。
- **开关 Wi-Fi/热点** `ExternalWifiManager.setWifiEnabled`、`ecarx.fw.api.wifi.TcamWifi`（含 SoftAP）。
- **按键拦截** `ecarx.car.ECarXCarHardKeyManager` / `adaptapi.input.Input.requestKeysInterception`（cookie 机制）。
- **HUD 读写** `adaptapi.hudinteraction.HUDInteraction`（`requestHUDMode` / `requestADASOpenStatus` / `getHUDCalibrationParam`）。
- **移屏/分屏** `MultiWindowImpl.moveActivityBetweenDisplay`、`EcarxSplitScreenManager`、副驾屏 `EcarxMultidisplayManager`。
- **VDBus 事件**（导航/HUD/投屏/手机互联/音频焦点/权限）+ `ecarx.fw.api.diminteraction.EcarxNaviInteraction`。
- **车况** `PhoneLinkAdaptorLibManager`（档位/电门/昼夜/倒车/车速/导航态）。
- 地图 HUD 通道 `isOpenHud=false`（[`吉利地图HUD显示机制.md`](../吉利地图HUD显示机制.md)）。

## 八、怎么验证（上车命令）

```sh
# 工程模式
adb shell am start -n com.desaysv.engmode/.MainActivity
# 看隐藏/停用与服务
adb shell pm list packages -d                 # disabled 包
adb shell dumpsys activity services com.geely.dimservice
adb shell getprop | grep -E 'persist\.sv\.|eol\.'
# 车型能力（需要工具/探针，见 samples/carprobe）
# 白名单/组件
adb shell content query --uri content://com.android.launcher3.interactive/shortcutEntity
```

> ⚠️ 工程模式里的「下线配置 / 烧录 / TBOX 升级 / ADB」属于产线用途，误操作可能改车机配置或刷坏固件，谨慎。

## 九、给 DiPlay 的可利用点（从「隐藏能力」里挑）

1. **ADB 已使能** + 工程模式可开 ADB → 前面 DiPlay 的「本机 adbd 开 Wi-Fi」仍有平台基础
   （但实测本机 adbd 不吃 TCP，见 [`车机兼容记录.md`](../车机兼容记录.md) 第七节）。
2. **Wi-Fi/WFD**：`persist.sys.wfd.*` 表明有 Wi-Fi Display；结合 `ExternalWifiManager` 可探索无线链路。
3. **投屏服务 `IProject`**：作为 `Presentation` 的备选投仪表路径。
4. **SV 调试/tcpdump 在跑**：抓包/日志可从 `/log` 取（诊断报告可直接引用）。
5. **工程模式的 CarPlay 页**（`CarPlayActivity`、`isCarplayITU`）说明车机对 CarPlay 有产线校验项，
   或许能反推原厂 CarPlay 的判定方式。
