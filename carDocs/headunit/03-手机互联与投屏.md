# 手机互联、投屏与互联应用

> 基于 `extracted/system` 拉取的原厂 APK + 框架 JAR（REA 静态分析，`evidence/*`）与
> `carDocs/车机兼容记录.md` 的实测结论交叉印证。

## 一、这台上都有哪些「手机互联」

| 应用/包 | 类型 | 说明 |
| --- | --- | --- |
| `com.geely.carlink`（`OneOS-CarLink`） | 系统 app | **「手机互联」HMI 客户端**：负责 CarLink/投屏的界面与车况适配 |
| `com.geely.hicar`（`OneOS-Hicar`） | 系统 priv-app | 华为 **HiCar** 车机侧 |
| `com.geely.flymelink`（`FlymeLink`） | 系统 priv-app | 魅族 **Flyme Link**（含「无界互联」） |
| `com.upuphone.starrynet`（`Starrynet`） | 系统 priv-app | 星纪魅族 **无界互联 / ICCOA**（Netty 栈） |
| `com.thunder.carplay`（`ThunderCarplay`） | 厂商 app | ⚠️ **不是 Apple CarPlay**：类几乎全是 `com.thunder.ktv`（雷石 KTV）+ 车载音效 + 麦克风音量 |
| `com.autolink.carplay` | 系统服务 | 文档中提到的「原厂 CarPlay 服务」；**本次提取的 117 个 APK 里没有**（可能在未拉取的分区） |
| `com.desaysv.ivi.phonelinkmanager`（phonelinklib） | 框架 | **手机互联状态/引导信息的 AIDL**（含 CarPlay） |
| `com.desaysv.ivi.phoneLinkplatformadaptorlib`（phonelinkadaptor） | 框架 | 互联 App 与车机之间的**适配层**（能力查询/车况回调） |

## 二、`OneOS-CarLink`（`com.geely.carlink`，2278 类）

结构与 `OneOS-Hicar`、`FlymeLink` 高度同构 —— 都是「互联 App 把车机能力适配给手机」。

> 启示：**互联 App 的标配是「按键 + 导航 + 车况 + 昼夜 + Dock + 语音」六路 handler**。
> DiPlay 目前只做了部分（方向盘键、仪表导航未通），可对照这些 handler 看车机期望的接入点。

## 三、`OneOS-Hicar`（`com.geely.hicar`，2823 类）

- `service.HiCarService` / `listener.HiCarServiceConnection`；`handler.key.KeyHandlerImpl`（**抢麦克风键**）。
- `app.CarConfigManager` / `HiCarConfigUtils`：按车型分支（`EX11AudioControl`/`G636AudioControl`/`kx11`），
  `handler.media.*`、`handler.audio.*`。
- `broadcast.HiCarBootReceiver`、`view.HiCarMainActivity`、`PinCodeDialog`、`HicarCallWindow`。
- 文档已证实：长按麦克风键会被 HiCar 抢去 `startHiCarMainActivity`；停用包 `com.geely.hicar` 即可让 DiPlay 接管。

> 新增线索：HiCar 的按键处理在 `com.geely.hicar.handler.key.KeyHandlerImpl`，与 `OneOS-CarLink` 同名同构 ——
> 说明**按键抢占用的是同一套 handler 框架**，第三方若要更干净地抢键，应研究这个 key handler 的注册方式。

## 四、`FlymeLink` + `Starrynet`（魅族系）

## 五、手机互联能力查询 —— `PhoneLinkAdaptorLibManager`

`com.desaysv.ivi.phoneLinkplatformadaptorlib.PhoneLinkAdaptorLibManager`（`evidence/inspect/phonelinkadaptor.Manager.json`）：

```java
boolean isSupportCarPlay();  boolean isSupportCarPlayWireless();  boolean getCarPlayConfig();
boolean getCarPlayITU();     boolean getCarPlayCertification();
boolean isSupportHiCar();    boolean isSupportHiCarWireless();     boolean isHicarCertificated();  boolean getHiCarConfig();
boolean isSupportCarLife();  boolean isSupportCarLifeWireless();
boolean isSupportAndroidAuto(); boolean isSupportAndroidAutoWireless(); boolean getAndroidAutoConfig();
```

> 这是**车机对「谁在互联、车现在什么状态」的权威来源**：是否在导航、是否倒车（RVC）、档位、

> `getCarPlayITU()` / `getCarPlayCertification()` 用于 CarPlay 认证/iAP2 相关判断。

## 六、CarPlay 状态与引导 —— `desaysv-phonelinklib.jar`

- `carplay.ICarplayManager`（`evidence/inspect/carplay.ICarplayManager.json`）：
  无线 CarPlay 扫描/连接/状态/设备列表 + `addCarplayCallback`。
- `carplay.CarPlayRouteGuidanceInfo`（字段）：`currentRoadName`、`destinationName`、`distanceRemaining`
  (+`DisplayString`/`DisplayUnits`)、`distanceRemainingToNextManeuver`、`estimatedTimeOfArrival`、
  `maneuverState`、`routeGuidanceManeuverCurrentList(int[])`、`routeGuidanceState`、`laneGuidance*`、
  `routeGuidanceBeingShownInApp`、`routeGuidanceDisplayComponentID`。
- `carplay.CarPlayLaneGuidanceInfo` / `CarPlayLaneInformation` / `CarPlayPhoneInfo` / `CarPlayTrackInfo` /
  `CarPlayTrackArtwork` / `WirelessCarPlayInfo` / `WirelessCarPlaySetupUUID` / `SupportedLocationInformation`。
- `ISvPhoneLinkDeviceService`：`checkCarPlayEnable()`、`getActivitingLinkDeviceType()`、
  `getLinkDeviceContextAll()`、`getLinkDeviceTypeListAll()`、`getWireLessLinkReconnectBtAddr(int)`、
  `getLinkDeviceTipStatus(int)`。

> `CarPlayRouteGuidanceInfo` / `CarPlayLaneGuidanceInfo` 是**车机侧 CarPlay 引导数据结构**，
> 说明这台上「CarPlay 引导 → 仪表/HUD」本来就有官方通道（由原厂 CarPlay + dimservice 完成）。
> DiPlay 是自建 CarPlay，若想投引导，最终仍受第四节（第九节）结论限制：**只有画面可投，导航内容受原厂引擎限制**。

## 七、投屏 —— `desay.projection.jar`

- `com.desaysv.ivi.projection.IProject`（AIDL）：`startProjectToDisplay`、
  **`startProjectToDisplayWithSurface(Surface, int, int)`**、`startProjectToDisplays(int,int[])`、
  `stopProjectForDisplay(s)`、`setAntiControllEnabled(int, boolean)`。
- `com.desaysv.ivi.vds.projection.DesaySVProjectManager`（`evidence/method/project.startProjectService.json`）：
  ```java
  Intent i = new Intent();
  i.setPackage(DESAY_PROJECT_SERVICE_PACKAGE);
  i.setAction(DESAY_PROJECT_SERVICE_INTERFACE_NAME);
  context.startForegroundService(i);
  context.bindService(i, mServiceConnectionListener, BIND_AUTO_CREATE);
  ```
  普通工具 `strings` 观测到：
  - action = **`action.desaysv.ivi.vds.projection.IProject`**
  - binder 服务名 = **`desaysv_project_service`**
  - 接口 = `com.desaysv.ivi.projection.IProject`
  - 绑定轮询常量 `DESAY_PROJECT_SERVICE_BINDER_*`、等待超时常量 `DESAY_PROJECT_WAIT_TIMEOUT_*`
  - 包名常量 `DESAY_PROJECT_SERVICE_PACKAGE`（值待运行期确认；日志 tag 为 `com.desaysv.ivi.vds.projection`）

> **可操作性**：只要能 `bindService(action.desaysv.ivi.vds.projection.IProject)`，就能调用
> `startProjectToDisplayWithSurface(surface, from, to)` —— 用**自己的 Surface** 投到指定 display。
> 这条与 DIM `Presentation` 并行，**可能比 `Presentation` 更「官方」**（不依赖 display 图层顺序）。
> 权限/白名单待上车验证。

## 十、结论与 DiPlay 待选项

| 目标 | 可尝试的通道 | 风险 |
| --- | --- | --- |
| CarPlay 画面投仪表 | 现方案 `Presentation` + DIM `notifyDimProjectScreenSwitch`；**备选** `IProject.startProjectToDisplayWithSurface` | 需验证第三方能否 bind `desaysv_project_service` |
| 判断车况/互联状态 | `PhoneLinkAdaptorLibManager`、`ISvPhoneLinkDeviceService` | 需权限；可只读 |
| 副驾屏 | `EcarxMultidisplayManager.setPsdDisplayOnAndOff` | 需权限 |
| 分屏 | `EcarxSplitScreenManager` / `MultiWindowImpl.moveActivityBetweenDisplay` | 可能影响车机桌面 |
| 手机互联状态 | `VDEventPhoneLink`、`ICarplayManager` | 与 DiPlay 自建 CarPlay 并存会互相干扰 |

> ⚠️ `com.thunder.carplay` **不是** Apple CarPlay（是 KTV 应用），原文 `01-系统盘点.md` 描述已更正。
