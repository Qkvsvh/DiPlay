## 五、签名权限与白名单（`permissions/`）

21 个 XML：`platform.xml`、`privapp-permissions-platform.xml`、`privapp-permissions-qti.xml`、
`privapp-permissions-ecarx.xml`、`desaysv_platform.xml`、`com.android.car.xml` 等。

- `desaysv_platform.xml`：只声明 `WRITE_MEDIA_STORAGE`（`media_rw`/`sdcard_rw` gid）。
- `privapp-permissions-ecarx.xml`：给 `com.ecarx.*` 的应用授系统级权限
  （`INSTALL_PACKAGES` / `WRITE_SECURE_SETTINGS` / `CHANGE_COMPONENT_ENABLED_STATE` / `READ_LOGS` 等）。
- 平台签名权限清单（`platform.xml`）定义了车厂私有权限，是判断「第三方能否调用某能力」的依据。

## 七、其它素材（仓库根目录）

`oneosapi-all.bin`（2.3 MB，未入库）：是一个 **DEX 文件**（`dex\n039`），REA 分析出 936 个类，
其中只有 24 个 `com.geely.lib.oneosapi` 类，其余为混淆的 `a.*`/`b.*` 与 AndroidX。
**不是完整的 OneOS API**（完整实现在各 `OneOS-*` APK 内，如 `OneOS-InputService` 内嵌整套 `com.geely.os.*`）。
参考价值有限。

## 复现命令

```sh
# REA 需要单独提供的 JADX 引擎（SHA-256 与 REA 审计值一致）
export REA_JADX_MCP_JAR="$HOME/.cache/rea/jadx-headless-mcp-0.7.1-all.jar"
npx -y rea-agents@6.4.0 inspect-android-package <apk> --format json

# 普通工具（观测标注为 aapt/getprop）
aapt2 dump badging <apk>
grep -i geely carDocs/extracted/system/getprop.txt
```
