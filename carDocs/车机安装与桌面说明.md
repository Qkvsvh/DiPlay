## 二、安装方式（重点：adb 需要特殊处理）

### 结论

这台车机**不能用普通 `adb install` 命令直接安装**。正确的做法是：

1. 用 `adb push` 把 APK 推到设备 `/data/local/tmp/`
2. 再用 **拆分关键字** 的方式调用设备的 `pm install` 安装

### 为什么普通方式不行

**坑 1：`adb install` 本身失败**

```
$ adb install -r DiPlay-0.2.13.apk
adb: failed to run abb_exec. Error: closed
adb: retrieving the default device installation mode failed: closed
Performing Streamed Install
adb: connect error for write: closed
```

车机不支持 adb 的**增量安装（abb_exec）**与**流式安装（streamed install）**，所以默认安装流程走不通。

**坑 2：`pm install` 被切断**

改用推送后再执行：

```
$ adb shell pm install -r /data/local/tmp/DiPlay-0.2.13.apk
error: closed
```

表面上像是连接不稳，但实际是——

**坑 3（真正的根因）：adbd 对命令字符串做了关键字过滤**

车机的 adbd 会检查 `adb shell` 收到的命令原文，**只要命令里出现 `install` 这个词，就直接强制断开连接**（吉利/领克的防篡改机制）。

验证方法：

```
$ adb shell 'echo pm'          → pm            （正常）
$ adb shell 'echo install'     → error: closed （被切断！）
$ adb shell 'pm path android'  → package:...   （正常，因为不含 install）
```

### 绕过方案：把关键字拆开拼接

让命令**原文里不出现 `install`**，交给设备端的 shell 再拼回去：

```bash
# 先推送
adb push DiPlay-0.2.13.apk /data/local/tmp/DiPlay-0.2.13.apk

# 再用变量拼接绕过关键字过滤
adb shell 'a=in; b=stall; pm ${a}${b} -r -t /data/local/tmp/DiPlay-0.2.13.apk'
```

输出：

```
Success
```

安装成功。

### 可复用安装脚本

配套脚本：**`install-apk.sh`**（与本文档同目录），把 APK 文件作为参数传入即可。

```bash
# 基本用法
./install-apk.sh DiPlay-0.2.13.apk

# 安装并授予全部权限
./install-apk.sh app.apk -g

# 覆盖 + 允许降级
./install-apk.sh app.apk -r -t -d
```

**选项**

| 选项 | 含义 |
|---|---|
| （默认） | 自动带 `-r -t`（覆盖安装、允许 test 包） |
| `-r` | 覆盖安装 |
| `-t` | 允许安装 test 包 |
| `-g` | 安装后授予全部运行时权限 |
| `-d` | 允许降级安装 |
| `-h` | 显示帮助 |

脚本做的事：`adb wait-for-device` → `adb push` 到 `/data/local/tmp` → 用关键字拆分方式调用 `pm install` → 清理临时文件 → 校验安装结果。

> 注意：若在脚本里直接写 `pm install`，命令原文仍会因含 `install` 被 car adbd 切断，所以脚本内部必须是拆分写法。

## 三、桌面环境

### 类型

**Flyme Auto（星纪魅族 / 领克 LYNK & CO）定制桌面**，底层仍是 AOSP 的 **Launcher3**（包名 `com.android.launcher3`），但被大幅改造。

### 布局特征

**1. 首页是固定卡片式桌面**（非传统图标网格），包含：

- 地图卡片（左上，带搜索）
- **应用建议**卡片（展示最近/推荐应用的图标）
- 音乐播放卡片
- 空调控制卡片（主/副驾通风）
- 氛围灯卡片
- 电话卡片

**2. 底部常驻系统栏**（`com.geely.statusbar`）：

- 左侧：Home / 「回到桌面」按钮
- 中间：音乐控件、温度调节、后视镜、空调 A/C 等车辆控制
- 右侧：应用列表（九宫格图标）

**3. 应用列表**分三个标签页：

| 标签 | 资源 ID | 说明 |
|---|---|---|
| 我的应用 | `ll_tab_all` | 已安装/预装的本地应用 |
| 小程序 | `ll_tab_service` | 轻应用（小程序） |
| 无界互联 | `ll_tab_desktop` | 手机互联（Flyme Link / HUAWEI HiCar / ICCOA Carlink 等） |

应用列表采用 `RelativeLayout + iv_app_icon + tv_app_title` 的结构，5 列网格排版。

### 桌面相关的关键包

| 组件 | 包名 |
|---|---|
| 桌面 | `com.android.launcher3` |
| 状态栏/系统栏 | `com.geely.statusbar` |
| 应用列表 Controller | `com.autolink.diminteraction`（可见于包列表） |

### 关于「添加到桌面」

- 该桌面 **没有注册第三方快捷方式接收器**（`INSTALL_SHORTCUT` 广播无响应会卡住），因此**不能用广播方式添加图标**。
- 添加方式通常是：在「我的应用」里**长按应用图标**，选择「添加到桌面」，或直接拖拽到首页卡片区。
- 通过 adb 自动化添加需要在 Launcher 内模拟触摸（`input tap` / `input swipe`），依赖具体 UI 坐标，稳定性较差。

## 四、命令速查

```bash
# 设备
adb devices -l

# 安装（推送 + 拆分关键字）
adb push app.apk /data/local/tmp/app.apk
adb shell 'a=in; b=stall; pm ${a}${b} -r -t /data/local/tmp/app.apk'

# 查询已安装
adb shell 'pm list packages | grep -i 关键字'
adb shell 'dumpsys package 包名 | grep -E "versionName|versionCode"'

# 启动应用
adb shell 'am start -n com.shihab.diplay/com.shilapi.xcertplay.DiPlayActivity'

# 截图 / UI 层级
adb exec-out screencap -p > screen.png
adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml .
```

## 五、排错备忘

| 现象 | 原因 | 处理 |
|---|---|---|
| `failed to run abb_exec` | 车机不支持增量/流式安装 | 改用 push + pm install |
| `error: closed`（pm install） | adbd 过滤含 `install` 的命令 | 拆分关键字 `a=in; b=stall` |
| `error: closed`（任意含 install 的命令） | 同上 | 拆分关键字 |
| `waiting for device` 死循环 | 传输通道状态错乱 | 重新插拔 USB / 重启 adb server |
| 应用不出现在「我的应用」 | 桌面为定制列表 | 应用抽屉内长按添加，或定位其自定义数据源 |
